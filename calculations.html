1.1 Cache 平均访问时间
Cache · Average Access Time
交互可视化 · 命中率滑块 → T 实时变化
单层 Cache
T = h · Tc + (1 − h) · Tm
分层 Cache（先 L1 再 L2 再主存）
T = h₁ · Tc₁ + (1 − h₁) · [h₂ · (Tc₁+Tc₂) + (1−h₂) · (Tc₁+Tm)]
▸ 典型题
Cache 访问 10 ns，主存 100 ns，命中率 90%。
T = 0.9 × 10 + 0.1 × 100 = 19 ns
陷阱：分层 Cache 不要漏算前级的访问时间（先查 L1 不命中才会查 L2）。

Pipeline · Throughput & Speedup

1.3 系统可靠性
×2真题考过2022·2023下
Reliability · Series / Parallel
交互可视化 · 串/并/N模冗余 三选一对比
串联（一个挂全挂）
R = R₁ · R₂ · … · Rn
并联（备份互为冗余）
R = 1 − (1−R₁)(1−R₂)…(1−Rn)
N 取 K 表决（K 个正常工作即可）
R = Σi=K..N C(N,i) · Rⁱ · (1−R)^(N−i)
▸ 典型题
3 个 R=0.9 模块串联：R = 0.9³ = 0.729
3 个 R=0.9 模块并联：R = 1−0.1³ = 0.999
铁律：串联降可靠，并联升可靠——多数题目要你识别结构（混合串并联要分层计算）。

1.6 子网划分
Subnetting & VLSM
交互可视化 · 32 位色带 + 子网段实时划分
/26
地址分类（A/B/C/D/E）
A 类：1.0.0.0 ~ 126.255.255.255 / 8 主机 2²⁴ − 2
B 类：128.0.0.0 ~ 191.255.255.255 / 16 主机 2¹⁶ − 2
C 类：192.0.0.0 ~ 223.255.255.255 / 24 主机 2⁸ − 2
子网数（借位）
子网数 = 2^(借位数)
每网可用主机数
可用主机 = 2^(剩余主机位) − 2 （减全 0 和全 1）
子网掩码速算
/n → 前 n 位为 1，后 (32−n) 位为 0
如 /26 → 255.255.255.192
子网聚合（CIDR 路由汇总）
汇总后 /n = max(各子网相同前缀位数)
▸ 典型题
C 类 192.168.10.0，要划分 4 个子网：
借位 = log₂4 = 2 位 → /26
子网掩码 = 255.255.255.192
每子网主机 = 2⁶ − 2 = 62 台
子网：0、64、128、192（每段 64）
陷阱：全 0 和全 1 子网在老协议中不可用，新协议（CIDR）可用——多数题目默认减 2。
1.7 IP ↔ 整数转换
IP Address ↔ Integer
交互可视化 · IP 各位权 + 二进制展开
IP → 整数
N = a·2²⁴ + b·2¹⁶ + c·2⁸ + d
a.b.c.d 为 IP 四段
整数 → IP
a = N >> 24 & 0xFF
b = N >> 16 & 0xFF
c = N >> 8 & 0xFF
d = N & 0xFF
▸ 典型题
192.168.1.10 → 192×2²⁴ + 168×2¹⁶ + 1×2⁸ + 10
= 3221225472 + 11010048 + 256 + 10
= 3 232 235 786
套路：写出二进制按 8 位分组，再转十进制；或用公式直接乘权重 2²⁴/2¹⁶/2⁸/1。

1.10 页式存储地址结构
×3真题考过2019下·2021·2025下
Paging · Page Number + Offset
交互可视化 · 地址拆分 + 页表点击查映射
▸ 页表（点击任一项查映射）
逻辑地址 = 页号 P + 页内偏移 W
页号位数 = log₂(页数)
页内偏移位数 = log₂(页大小)
物理地址 = 物理块号 + 页内偏移
物理地址 = f(页号) × 页大小 + 页内偏移
f(页号) = 页表查得的物理块号
总位数换算
页表项数 = 2^(页号位数)
页表大小 = 页表项数 × (每项位数 / 8)
缺页率
f = 缺页次数 / 总访问次数
平均访问时间（含快表 TLB）
T = h·tTLB + (1−h)·(tTLB + tM) + tM
h = TLB 命中率，tM = 访问主存时间
▸ 典型题
逻辑地址 32 位，页大小 4 KB = 2¹² 字节
页内偏移 = 12 位 → 页号 = 32 − 12 = 20 位
页数 = 2²⁰ = 1M 页
物理地址 32 位 → 物理块号 = 32 − 12 = 20 位
页表大小 = 2²⁰ × 4 B = 4 MB
陷阱：页大小是 2 的幂（如 4K/8K/16K），偏移位数才是 log₂；混淆位数会全错。

1.13 银行家算法
×1真题考过2025上
Banker's Algorithm for Deadlock Avoidance
交互器 · 编辑 Max/Allocation 矩阵 + 自动跑安全算法
核心矩阵
Max[i,j] = 进程 i 对资源 j 的最大需求
Allocation[i,j] = 已分配
Need[i,j] = Max − Allocation
Available = 总资源 − ΣAllocation
安全判定
① Work = Available，Finish[i] = false
② 找 i：Finish[i]=false 且 Need[i] ≤ Work
③ Work += Allocation[i]；Finish[i]=true；回到 ②
④ 若所有 Finish[i]=true → 安全，否则不安全
不死锁最小资源数
Rmin = N × (M − 1) + 1
N = 进程数，M = 每个进程最大需求
▸ 典型题
3 进程，每个最多需 5 个同类资源
不死锁最小资源数 = 3×(5−1)+1 = 13 个

ES = max(前置 EF) ← 最早开始
EF = ES + 工期 ← 最早完成
LF = min(后续 LS) ← 最晚完成
LS = LF − 工期 ← 最晚开始
TF = LS − ES = LF − EF ← 总时差
FF = 后继 ES − EF ← 自由时差
关键路径特征：TF=0 的活动组成的路径；可能有多条；决定项目工期。
▸ 计算顺序
  1. 正向算 ES / EF（从左到右）
  2. 反向算 LF / LS（从右到左）
  3. 求 TF = LS − ES（=0 即关键活动）
  4. 串联 TF=0 的活动 → 关键路径

4.2 三点估算 PERT
×2真题考过2021·2024下
Three-Point Estimation
交互可视化 · β 分布 + Z 值完工概率
乐观 O
4
最可能 M
6
悲观 P
8
期望工期
E = (O + 4M + P) / 6
O = 乐观，M = 最可能，P = 悲观
方差与标准差
σ² = ((P − O) / 6)²
σ = (P − O) / 6
关键路径上的总方差
σtotal² = Σσi² （仅关键路径活动）
完工概率（正态分布）
Z = (Tdeadline − Ecritical) / σtotal
查标准正态表得 P(Z)
▸ 典型题
A=4, M=6, B=8 → E = (4+24+8)/6 = 6 天，σ = (8−4)/6 = 0.67

4.3 挣值管理 EVM ⭐必考
×N真题考过案例 T3/T4 必考
Earned Value Management
交互计算器 · 输入四个值自动算 EAC/ETC/VAC
进度偏差 SV
SV = 0
成本偏差 CV
CV = 0
三个基础值
PV = Planned Value 计划值
EV = Earned Value 挣值（已完成工作的预算）
AC = Actual Cost 实际成本
偏差
SV = EV − PV (>0 超前，<0 落后)
CV = EV − AC (>0 节约，<0 超支)
绩效指数
SPI = EV / PV (>1 超前，<1 落后)
CPI = EV / AC (>1 节约，<1 超支)
预测公式
BAC = 完工预算
EAC = BAC / CPI ← 典型性差异
ETC = EAC − AC
VAC = BAC − EAC ← 完工偏差
▸ 典型题
计划 10 万，AC=5.5 万，完成了 PV=5 万对应的 EV=4 万
SV = 4−5 = −1（落后）
CV = 4−5.5 = −1.5（超支）
SPI = 0.8，CPI = 0.73
EAC = 10 / 0.73 ≈ 13.7 万
陷阱：题目常给"完成 50%"、"完成 100% 的 40%"，要先把 EV 算出来再用。

5.3 敏感 / 权衡 / 风险点
Sensitivity / Tradeoff / Risk Point
◉
敏感点
影响一个质量属性的单个决策
答题关键词：对性能有重大影响 / 对可用性是关键 / 是 A 属性的决定性因素

案例：缓存命中率 95% 是性能属性的敏感点。
⇄
权衡点
影响多个质量属性，且这些属性之间存在矛盾
答题关键词：A↑则 B↓ / 提升了 X 但牺牲了 Y / 在 ... 与 ... 之间权衡

案例：加密强度↑（安全性↑）vs 性能↓（响应时间↑）。
⚠
风险点
存在潜在问题的架构决策，需要降低或消除
答题关键词：可能导致 / 存在 ... 风险 / 建议采用 ... 缓解

案例：单点故障可能导致系统不可用，建议采用主从热备。
✓
非风险点
已经分析过无问题的决策，可放心采用
答题关键词：已分析 / 不存在风险 / 可放心采用 / 满足 ... 要求

案例：bcrypt + salt 已分析无安全风险。
术语定义答题关键词
敏感点影响一个质量属性的决策对性能有重大影响
权衡点影响多个质量属性的决策A↑则 B↓
风险点有潜在问题的决策可能导致...
非风险点已分析无问题可放心采用
▸ 答题模板
风险点：X 方案可能导致 A 性能瓶颈，建议采用 Y 方案。
权衡点：使用缓存会提升性能（响应时间↓），但降低数据一致性（数据安全↓）。
陷阱：风险点 ≠ 不好的点；要写成"决策+风险+建议"。

6.1 信道容量
×2真题考过2024上·2025上
Nyquist & Shannon
双公式对比 · 奈氏（无噪声）+ 香农（有噪声）+ dB 换算
奈奎斯特（无噪声）
0 bps
C = 2W · log₂(N) = 2 × 3000 × log₂(4)
香农（有噪声上限）
0 bps
C = W · log₂(1 + S/N) = 3000 × log₂(1 + 1000)
💡 奈氏是理论速率，香农是噪声环境下的实际上限。 二者取小 = 工程可用带宽。
⚠ dB ↔ 线性换算：S/N（线性）= 10^(dB/10)。例：30 dB → 1000 倍。
奈奎斯特定理（无噪声）
C = 2W · log₂(N)
W = 带宽 Hz，N = 信号级数
香农定理（有噪声）
C = W · log₂(1 + S/N)
S/N = 信噪比，dB 表示
区分：奈氏用于理想无噪声；香农用于有噪声上限；考试二者给单位（bit/s）。
陷阱：S/N 给的是 dB 值时先换算：S/N（线性）= 10^(dB/10)。

6.3 性能与容量估算
×N真题考过案例题常考
Performance & Capacity · 案例高频
交互计算器 · 漏斗式自动算机器数
流量估算三步法
  1. PV = 日活用户数 × 每人每天访问次数
  2. 平均 QPS = PV / 86400（按全天）
  3. 峰值 QPS = 平均 QPS × 峰值倍数（电商 5-10、秒杀 10-20）
核心公式汇总
PV = DAU × 访问频次
平均 QPS = PV / 86400
峰值 QPS = 平均 QPS × 峰值倍数
机器数 = ceil(峰值 QPS / 单机 QPS)
单机带宽 (bps) = 页面平均大小 × 单机 QPS × 8
存储量 (GB) = (PV × 页面平均 KB) / 1024 / 1024
常见经验值
指标参考值
普通 Web 页面200 KB（不含图片）/ 1-2 MB（含图）
API 接口响应10-50 KB
单机 QPS（4 核 8G 优化）500-1500（读多写少）
电商峰值倍数5-10×
秒杀峰值倍数10-20×
关系型 DB 单机 QPS1000-3000
Redis 单机 QPS50000-100000
▸ 典型题
场景：电商日活 100 万，每人每天访问 5 次，页面 200 KB
PV = 100 万 × 5 = 500 万
平均 QPS = 500 万 / 86400 ≈ 57.9 QPS
峰值 QPS = 57.9 × 10 = 579 QPS
机器数 = ceil(579 / 800) = 1 台（读多写少；写多至少 3-5 台）
存储量 = 500 万 × 200 KB / 1024² ≈ 954 GB/天
答题铁律：PV → QPS → 峰值 → 机器数 4 步走；每步标单位；给单机参考值才会算对。
陷阱：① 峰值倍数常被遗漏（秒杀 / 双 11）；② 写场景（订单）需 + 2-3 倍冗余；③ DB 与缓存单机 QPS 数量级差 10×。
